# Как сделать модель по ТЗ

ТЗ — [`MODEL_SPEC.md`](MODEL_SPEC.md). Модель строится кодом в three.js, потом проходит сборку в Blender 5 и проверку.

```bash
pip install bpy                                    # Blender 5 как Python-модуль, один раз
# 1. генератор three.js -> source.glb (GLTFExporter, binary, animations)
python tools/finalize_model.py source.glb out/ Cargo_Truck --zip-name="Грузовик КамАЗ-5320"  # 2. сборка
python tools/check_model.py "out/Грузовик КамАЗ-5320.zip"   # 3. проверка (сборка запускает её сама)
node tools/check_gaps.mjs out/Cargo_Truck.glb --out=out/gaps  # 4. сквозные щели (нужны playwright и three)
```

Архив называется точно как лодка или корабль в задании, русские слова по-русски (правило в начале ТЗ):
`--zip-name="Тип Л «Ленинец», серия II (СССР)"`. Файлы внутри — по латинскому корню.
Сдаётся архив, только если проверка пишет «Готово к сдаче: ни ошибок, ни предупреждений», а `check_gaps.mjs` —
«Сквозных щелей не найдено». Если three не установлен рядом, путь к нему: `--three=путь/к/node_modules/three`.
На снимках в `--out` красное — изнанка, видная сквозь щель.

## Что делает сборка (`tools/finalize_model.py`)

Импорт в Blender, один корень с именем модели. Дальше по порядку:
- поворот и масштаб применяются в сетку;
- вершины сливаются (0,1 мм), удаляются висящие вершины и вырожденные грани;
- n-гоны разбиваются на треугольники, сглаживание по углу 30°;
- нормали наружу: замкнутые куски разворачивает Blender, открытые (переборка, щит, борт без крышки) — лицом туда,
  откуда их видно (лучи из граней по всей модели). Иначе грань бывает задом к зрителю и в корпусе видна «дыра»;
- текстуры подгоняются до степени двойки ≤ 2048;
- модель встаёт самой низкой точкой на Y = 0 и центруется по X и Z;
- камеры, свет и пустые узлы удаляются;
- картинки упаковываются, сохраняется `.blend`, по п. 10 ТЗ экспортируется `.glb`, всё собирается в `.zip`.

## Что должен сделать генератор (сборка это не исправит)

- **Бюджет** «Большой техники»: ≤ 110 000 треугольников, ≤ 9 материалов, ≤ 150 узлов. Узлы считаются все, включая группы.
  Неподвижные детали одного материала склеивать (`BufferGeometryUtils.mergeGeometries`) в одну сетку на смысловую группу:
  `Superstructure_Steel`, `Deck_Fittings`. Отдельными узлами оставлять только подвижные части и зоны попадания.
- **Материалы**: только `MeshStandardMaterial`, имена по смыслу (`Hull_Steel`, `Deck`, `Glass`). Мелочи — цветом
  материала без текстуры. Окраску, номера и надписи — в одну текстуру-атлас, а не в отдельный материал на каждую.
- **UV только в 0…1.** Повторяющийся узор (плитка, решётка) — через `texture.repeat` (экспортируется как
  `KHR_texture_transform`), а UV сетки нормировать в 0…1. Текстуры на холсте — степень двойки, сторона ≤ 2048.
- **Имена**: у каждого `Mesh` и `Group` — латиница, по смыслу, уникальные, повторы с `_1`, `_2` или `_L`, `_R`.
  Корень — `Group` с именем модели (`Pyotr_Velikiy`).
- **Подвижные части** (винт, крышка, башня, антенна): отдельная `Group`, **поворот в покое 0**, начало на оси движения.
  Наклон оси или повёрнутую форму запечь в геометрию детей, а не в поворот узла. Подвижная часть не внутри другой подвижной.
  Анимируются только `quaternion` и `position`. Полный оборот — не меньше 5 ключей, повторяющийся клип замкнут.
- **Масштаб узлов 1**, без зеркал: зеркальную копию делать через `geometry.scale(-1, 1, 1)` с разворотом индексов, а не
  `mesh.scale.x = -1`.
- **Оси**: метры, Y вверх, перёд +X, правая сторона +Z. Самая низкая точка встаёт на Y = 0: у корабля это киль, а ватерлиния
  оказывается на высоте осадки (её указать в паспорте).
- **Стыки без щелей**: переборка, палуба и борт сходятся в одних точках. Если шпангоуты наклонные, переборку
  ставить по точкам шпангоута, а не на ровное `x`, иначе между палубой и переборкой останется щель.
- **Открытые оболочки замкнуть**: фонарь кабины, щит, тент — с задней стенкой или толщиной, иначе сзади видно небо.
- Лёгкая копия ≤ 30 000 треугольников получается упрощением: крупные формы — отдельными замкнутыми телами,
  мелочь (швы, люки, заклёпки) — в текстуре, а не в сетке.
